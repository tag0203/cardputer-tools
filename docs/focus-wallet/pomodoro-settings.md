# ポモドーロ設定仕様

この文書は、Cardputer版Focus Walletに現在実装されているポモドーロ設定と報酬ルールの正確な挙動をまとめたものです。

実装の正本:

- 設定画面・値変更: [`screen_settings.h`](../../src/focus_wallet/screen_settings.h)
- 初期値・タイマー・報酬・日付変更: [`focus_wallet.ino`](../../src/focus_wallet/focus_wallet.ino)

## 設定画面の操作

Focus Walletの待機画面で`S`を押すと設定画面を開きます。

| キー | 動作 |
| --- | --- |
| `↑` / `↓` | 設定項目を移動 |
| `←` / `→` | 選択中の値を変更 |
| `H` | Focus Walletへ戻る |

Cardputer ADVでは、メニュー操作中にFnを押す必要はありません。設定変更は操作した時点でPreferencesへ保存されます。

## 設定項目

| 画面表示 | 内容 | 初期値 | 範囲 | 変更単位 |
| --- | --- | ---: | ---: | ---: |
| `Focus` | 1回の集中時間 | 25分 | 1〜120分 | 1分 |
| `Short break` | 短い休憩時間 | 5分 | 1〜60分 | 1分 |
| `Long break` | 長い休憩時間 | 15分 | 1〜120分 | 1分 |
| `Pomodoros` | 1サイクルに必要な集中完了回数 | 4回 | 1〜12回 | 1回 |
| `Reward` | サイクル達成時に付与する自由時間 | 60分 | 5〜240分 | 5分 |
| `Wallet cap` | 保有できる自由時間残高の上限 | 180分 | 15〜1,440分 | 15分 |
| `Daily cap` | 1日に獲得できる自由時間の上限 | 無制限 | 0〜1,440分 | 30分 |
| `Carry over` | 自由時間残高を翌日へ繰り越す | OFF | ON / OFF | 切り替え |
| `Auto break` | 集中完了後に短い休憩を自動開始 | OFF | ON / OFF | 切り替え |
| `Auto focus` | 休憩完了後に集中を自動開始 | OFF | ON / OFF | 切り替え |
| `Sound` | 操作音と完了音 | ON | ON / OFF | 切り替え |

`Daily cap`の`0分`は画面上では`Unlimited`と表示され、獲得上限なしとして扱います。

## 変更が反映されるタイミング

- 時間設定の変更は、次に開始するセッションから使われます。
- 実行中または一時停止中のタイマー時間は変更されません。
- 実行中セッションは、開始時の時間を`plannedSeconds`として保持します。
- `Wallet cap`を現在残高より低い値へ変更すると、自由時間残高は新しい上限まで即時に切り詰められます。切り詰められた分は戻りません。
- その他の設定値も変更した瞬間に保存され、再起動後も維持されます。

## 集中完了とサイクル進捗

集中タイマーが0秒まで到達した場合にのみ、集中完了として次を行います。

1. 当日の完了回数を1増やす。
2. 当日の集中時間へ、そのセッションの予定時間を加算する。
3. 現在サイクルの完了回数を1増やす。
4. `Pomodoros`で設定した必要回数に達したら、自由時間の付与を計算する。
5. サイクル進捗を0へ戻す。

一時停止は残り時間を保持します。完了前にキャンセルした集中は、完了回数やサイクル進捗へ加算されません。

## 自由時間の付与計算

サイクル達成時の付与時間は、以下の3つで決まります。

```text
設定したReward
  ↓ Daily capの残りまでに制限
  ↓ Wallet capの空きまでに制限
実際の付与時間
```

計算式のイメージ:

```text
日次上限の空き = Daily cap - 本日の獲得時間
残高上限の空き = Wallet cap - 現在の自由時間残高

実際の付与時間 = min(Reward, 日次上限の空き, 残高上限の空き)
```

`Daily cap`が`Unlimited`の場合は、日次上限による制限を行いません。

### 例1: Wallet capで制限される

```text
Reward:       60分
Wallet cap:  180分
現在残高:    150分
実際の付与:   30分
付与後残高:  180分
```

### 例2: Daily capで制限される

```text
Reward:          60分
Daily cap:       90分
本日の獲得済み:  60分
実際の付与:      30分
```

上限の空きがない場合、実際の付与時間は0分になります。その場合でもサイクルは達成扱いとなり、進捗は0へ戻ります。

## 自由時間の利用

- `U`で現在の自由時間残高すべてを上限とする自由時間タイマーを開始します。
- 使用中は1秒ごとに残高とタイマー残り時間を減らします。
- 消費した秒数は当日の使用時間へ加算します。
- 一時停止中は消費しません。
- 途中でキャンセルした場合、すでに消費した時間だけが差し引かれ、未使用分は残高に残ります。
- 残高が0になると自動終了します。
- RTCまたは有効なシステム時刻がある場合、再起動中に経過した時間も復元時に消費します。

## 自動開始

### Auto break

ONの場合、通常の集中完了後に短い休憩を自動開始します。

サイクル達成時は完了結果と報酬を確認できるよう、自動休憩を開始しません。これは上限により実際の付与が0分になった場合も同じです。

### Auto focus

ONの場合、短い休憩または長い休憩が完了すると、次の集中を自動開始します。

### Sound

OFFにすると、キー操作時の短い音と、タイマー完了時の完了音の両方を停止します。タイマーや画面表示には影響しません。

集中、短い休憩、長い休憩、自由時間のいずれかが完了すると、減光中のバックライトは通常輝度へ戻ります。完了音をOFFにしていても、この画面復帰は有効です。

## 日付変更時の処理

有効なJST日付を取得でき、日付が変わったことを検出すると次を行います。

1. 前日の実績を履歴へ移す。
2. 当日の完了回数、集中時間、獲得時間、使用時間を0へ戻す。
3. サイクル進捗を0へ戻す。
4. `Carry over`がOFFなら自由時間残高を0へ戻す。

自由時間を使用中または一時停止中に日付が変わった場合は、その自由時間セッションを維持するため、日付変更時点では残高を0にしません。

## 保存と復元

設定、サイクル進捗、自由時間残高、当日実績、直近7日分の履歴、実行中タイマーはPreferencesへ保存します。

- 動作中は約10秒ごとに状態を保存します。
- 開始、一時停止、再開、キャンセル、完了、設定変更時にも保存します。
- 信頼できる時刻がある場合は、保存時刻との差から電源断中の経過を復元します。
- 信頼できる時刻がない場合は、不正な集中完了を防ぐため残り時間を保持した一時停止状態で復元します。
- 7日を超える時刻差は端末時刻の変更とみなし、一時停止状態で復元します。

## 実装変更時の確認項目

- 初期値を変えた場合、設定表と`Settings`構造体が一致しているか。
- 範囲や変更単位を変えた場合、`adjustSetting()`と本書が一致しているか。
- 実行中タイマーへ設定変更が遡及していないか。
- Daily capとWallet capを同時に超えるケースで、付与値が小さい方の空きに制限されるか。
- Wallet capを下げた時の残高切り詰めが意図どおりか。
- Carry overのON/OFFと、自由時間中の日付変更を確認したか。
- Auto breakがサイクル達成画面を飛ばしていないか。
- 設定と進捗が再起動後も復元されるか。
